## Redis Streams

Redis Stream - тип данных в Redis, который представляет из себя
 список, в который можно добавлять записи. Каждая запись в списке имеет свой уникальный `id`. 
По умолчанию он генерируется автоматически.

Запустим инстанс редиса в докере и попробуем создать поток:
```yaml
services:
  redis:
    image: redis:latest
    container_name: redis
    ports:
      - "6379:6379"
```

```bash
docker compose up -d
```

Чтобы подключится к редису выполним команду:
```bash
docker exec -it redis redis-cli
```

Проверить, что редис доступен можно командой:
```bash
127.0.0.1:6379> PING
PONG
```

### Работа со stream

Создадим поток и добавим несколько сообщений. 
Команда `XADD` добавляет запись в stream. 

Запись состоит из одной или нескольких пар ключ-значение.

```bash
XADD mystream * sensor-id 1234 temperature 19.8
"1778617125232-0"
```

В ответ мы получаем сгенерированный `id` нашей записи, он состоит из двух частей:
`{millisecondsTime}-{sequenceNumber}`

Свой `id` можно передать вместе `*`:
```bash
127.0.0.1:6379> XADD somestream 0-1 field value
"0-1"
127.0.0.1:6379> XADD somestream 0-2 foo bar
"0-2"
```

В этом случае вы должны сами следить за 
увеличением идентификатора.

Число записей в потоке можно посмотреть командой `XLEN`:
```
XLEN somestream
```

### Запросы по диапазону — XRANGE и XREVRANGE

Чтобы запросить данные по диапазону, нужно указать два идентификатора - 
начало и конец диапазона. 

Также существуют два специальных идентификатора "-" и "+", соответственно означающие самый маленький (первая запись) и 
самый большой (последняя запись) идентификатор в потоке.

```bash
XRANGE somestream - +
XRANGE somestream - + COUNT 2
XREVRANGE somestream + -
XREVRANGE somestream + - COUNT 2
```

### Чтение новых записей с помощью XREAD

Часто возникает задача подписаться на поток и получать только новые сообщения. 
Этого можно достичь используя команду `XREAD`.

#### Неблокирующая форма

```
XREAD STREAMS somestream 0
XREAD STREAMS somestream $
```
- `0` - означает читать сообщения с самого начала
- `$` - читать сообщения со следующего за последним

Неблокирующая форма `XREAD` означает, что команда возыращает ответ сразу, даже
 если в потоке нет сообщений.


#### Блокирующая форма

```
XREAD BLOCK 1000 STREAMS somestream $
XREAD BLOCK 0 COUNT 2 STREAMS somestream 0-1 
```
- `1000` - число миллисекунд ожидания новых сообщений (0 - бесконченое ожидание)

Если команда сможет обслужить наш запрос немедленно, без блокировки, 
она сделает это, в противном случае она заблокируется.


### Consumer Groups

В определенных задачах мы хотим разграничить доступ подписчиков к 
сообщениям внутри одного потока. Примером, когда это может быть полезно - очередь сообщений с воркерами, 
которые будут получать разные сообщения потока, позволяя масштабировать обработку сообщений.

Чтобы получить этот эффект, Redis Stream использует концепцию, 
называемую Consumer Group.

#### Создание группы

`XGROUP` используется для создания, уничтожения и управления группами.
```
XGROUP CREATE somestream mygroup $
```

При создании группы мы должны передать идентификатор, начиная с которого 
группа будет получать сообщения.

Теперь, когда группа создана, мы можем сразу же начать читать сообщения с 
помощью команды `XREADGROUP`. Эта команда очень похожа на `XREAD` и 
поддерживает необязательную опцию `BLOCK`. 

Однако есть обязательная опция `GROUP`, которая должна быть всегда указана 
c двумя аргументами: _имя группы_ и _имя подписчика_.

Пример команды:
```
XREADGROUP GROUP mygroup Alice COUNT 1 STREAMS somestream >
```
Интерпретация: _"Я, Алиса-подписчик, член группы mygroup, хочу прочитать 
из потока mystream одно сообщение, которое никогда не было никому доставлено 
ранее"_

- `Alice` - это `id` консьюмера внутри группы.
- `>` - специальный идентификатор фильтрует сообщения, оставляя только те, которые до сих пор ни разу не доставлялись

Если вместо `>` указать `0`, то получим еще не окнутые сообщения консьюмера.

Для того чтобы подтвердить чтение сообщение в группе, нужно отправить команду:
```
XACK somestream mygroup <id>
```

Посмотреть сообщения в статусе ожидания подтверждения:
```
XPENDING somestream mygroup
```

Сменить владельца pending сообщения можно командой:
```
XCLAIM somestream mygroup Alice 1000 <id>
```

Получить подробную информацию о сущностях можно:
```
XINFO HELP
```

### Ограничение размера потока

```
XADD mystream MAXLEN 2 * value 1
```
- `MAXLEN 2` - ограничевает размер потока в 2 записи, старые удаляются
